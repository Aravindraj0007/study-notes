Stage 1.1 — Cloud Computing Basics

Cloud Computing Fundamentals

Definition: Cloud computing is the delivery of computing resources (servers, storage, databases, software) over the internet, on-demand, with pay-per-use pricing — instead of owning and maintaining physical hardware.

Four defining properties:

PropertyMeaning
On-demandGet resources instantly, no procurement delay
Pay-as-you-goCharged only for what you use, no idle cost
Elasticity/ScalabilityResources grow/shrink automatically with demand
Managed infrastructureProvider handles hardware, cooling, maintenance

Easy example: Think of Ola/Uber. You don't own the car, you don't service it, you don't pay when you're not riding — you just book it when needed and pay only for that trip. Netflix doesn't own a million physical computers; it rents exactly as much computing power as it needs from AWS, and that amount changes automatically — more servers during peak evening hours, fewer at 4 AM.

Deployment models:

  • Public cloud — shared infrastructure, owned by provider (AWS, Azure, GCP). Example: any startup using AWS.
  • Private cloud — dedicated infrastructure for one organization. Example: a bank running its own private servers for extra security.
  • Hybrid cloud — mix of both. Example: a hospital keeping patient records on a private cloud but using public cloud for its website.

Overview of Major Providers

ProviderOwnerKnown for
AWSAmazonLargest market share, most mature, widest service range
AzureMicrosoftStrong with enterprises already on Microsoft stack
GCPGoogleStrong in data analytics and ML (BigQuery, Vertex AI)

Easy example: Like Swiggy, Zomato, and Uber Eats — three food delivery apps that all do the same job, just with different branding and slightly different strengths. AWS/Azure/GCP rent you the same kind of computing services, just under different names.

Exam point: Most cloud analytics concepts are provider-agnostic — the same service exists under a different name on each platform. Learn AWS deeply (your syllabus leans this way), and map Azure/GCP as synonyms.

Stage 1.2 — Core Cloud Services

Three building blocks everything else in this course sits on top of.

Compute

  • Rented processing power — a virtual machine you configure (CPU, RAM, OS).
  • AWS: EC2 | Azure: Virtual Machines | GCP: Compute Engine
  • Easy example: Like renting a laptop for a month instead of buying one. Choose how powerful it is, run your app on it, stop paying when you're done.

Object Storage

  • Storage for files (unstructured/semi-structured) — a flat space where each file has a unique "key," not a traditional folder system.
  • AWS: S3 | Azure: Blob Storage | GCP: Cloud Storage
  • Easy example: Like Google Drive. Dump any file — photos, videos, datasets — each with its own link. Instagram stores every uploaded photo this way.

Databases — Managed SQL

  • A relational (SQL) database where the provider handles setup, patching, backups, and scaling.
  • AWS: RDS | Azure: SQL Database | GCP: Cloud SQL
  • Easy example: Like an Excel sheet with rows/columns (e.g., a college's student database), except the provider backs it up and keeps it running so you never touch the server.

Why not just store everything in Object Storage? S3 can hold a file with SQL-style data, but it can't run queries on it — you'd have to download the whole file and search manually. RDS actually understands rows/columns and lets you ask "show me marks above 90" directly and instantly. Object storage is a locker; a database is an indexed library.

Memory hook: Compute = does the work, Storage = holds the files, Managed SQL = organizes and queries structured records.

Stage 1.3 — Landscape of Cloud Analytics

Once you have Compute + Storage + Database, companies build analytics systems on top. Five pieces, usually working together in a pipeline:

Data Warehousing

  • A database tuned for analysis (OLAP), not transactions (OLTP). Stores data column-by-column so it can scan millions of rows on one field fast.
  • Tools: Redshift (AWS), Synapse (Azure), BigQuery (GCP)
  • Easy example: Flipkart's checkout system (RDS) places one order in milliseconds. Flipkart's warehouse (Redshift) answers "total revenue by state, by category, last 3 years" in seconds — a completely different job.

Data Lakes

  • Raw, unstructured storage (built on object storage) — store first, structure later. Called schema-on-read, vs. a warehouse's schema-on-write.
  • Easy example: Uber's data lake stores every GPS ping raw and unsorted, because at collection time they don't know exactly what analysis they'll run later.

ETL/ELT

  • The pipeline that moves data from source to destination:
  • Extract — pull data out of the source
  • Transform — clean, dedupe, reshape it
  • Load — place it into the destination
  • ETL: transform before loading (used for warehouses, needs clean structured data going in)
  • ELT: load raw first, transform later, inside the destination itself (modern, lake-friendly)
  • Easy example: ETL = washing clothes before putting them in the cupboard. ELT = dumping clothes in first, washing only what you need to wear.

ML Platforms

  • Managed environment to train, deploy, and serve ML models without owning GPU hardware.
  • Tools: SageMaker (AWS), Azure ML, Vertex AI (GCP)
  • Easy example: Like using a photocopy shop instead of buying your own printer — rent the platform, upload data, it trains/deploys the model for you.

Visualization Tools (overview — deep dive in Module 5)

  • Dashboards that connect to a warehouse/lake and turn raw numbers into charts.
  • Example: Power BI
  • Easy example: Like a school report card — raw marks turned into a simple summary a parent can read at a glance.

Stage 1.4 — Big Data Fundamentals

Big Data — Characteristics (the 3 Vs)

  1. Volume — massive scale (terabytes to petabytes). Facebook generates 4+ petabytes daily. → Why cloud helps: object storage (S3) scales storage infinitely and cheaply; a single on-prem server/disk array simply can't hold or grow to this scale on demand.
  2. Velocity — speed of arrival (real-time feeds). Every swipe on Zomato, every live cricket score update. → Why cloud helps: serverless/streaming services (Lambda, Kafka on managed clusters — Module 4) can absorb sudden bursts of incoming events without you pre-provisioning capacity for the worst case.
  3. Variety — mixed formats (text, images, video, logs). WhatsApp handles text, voice, images, video, location — all at once. → Why cloud helps: object storage doesn't care about file type/schema, so all varieties land in the same lake without needing a different system per format.

Extended (5 Vs, sometimes asked):

  1. Veracity — trustworthiness of data. Fake reviews on Amazon reduce veracity. → Why cloud helps: data catalogs and metadata tools (Module 2) plus validation steps in ETL pipelines (Module 4) let you flag/quarantine untrustworthy data before it reaches analytics, at a scale no manual review process could match.
  2. Value — whether the data is actually useful. A million random tweets are useless unless you extract real sentiment from them. → Why cloud helps: cheap storage (keep everything) + on-demand ML platforms (SageMaker/Vertex AI) mean you can affordably run experiments to find the value later, instead of deciding upfront what's worth keeping.

Why it matters: A single server can't handle data at this scale/speed — that's exactly why Hadoop and Spark exist.

Hadoop

  • Original distributed processing framework. Core mechanism: MapReduce.
  • Map — split the big job into small pieces, process each on a different machine
  • Reduce — combine all small results into one final answer
  • Easy example: Counting national election votes — each state counts its own votes first (Map), then all totals get added up (Reduce).
  • Limitation: writes intermediate results to disk at every step → slower.

Concrete example — Word Count (the "Hello World" of MapReduce):

Input (3 lines spread across 3 machines):

Machine 1: "the cat sat"
Machine 2: "the dog ran"
Machine 3: "the cat ran"

Map step (each machine emits word: 1 pairs independently):

M1 → (the,1) (cat,1) (sat,1)
M2 → (the,1) (dog,1) (ran,1)
M3 → (the,1) (cat,1) (ran,1)

Shuffle (group same words together, across machines):

the → [1,1,1]
cat → [1,1]
sat → [1]
dog → [1]
ran → [1,1]

Reduce step (sum each group):

the: 3, cat: 2, sat: 1, dog: 1, ran: 2

Spark

  • Faster alternative — keeps data in memory (RAM) instead of disk → 10–100x faster.
  • Also handles streaming, SQL, and ML — not just batch processing like Hadoop.
  • Easy example: Hadoop is a student writing every rough step on paper. Spark solves it mentally, only writing the final answer.

On the cloud: you don't install Hadoop/Spark manually — you spin up a managed cluster (AWS EMR, Databricks) that's pre-configured.

The same word count in PySpark (what you'd actually run on a managed Spark cluster):

from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("WordCount").getOrCreate()
text = spark.sparkContext.textFile("s3://my-bucket/input.txt")

counts = (text
          .flatMap(lambda line: line.split(" "))   # Map
          .map(lambda word: (word, 1))
          .reduceByKey(lambda a, b: a + b))          # Reduce

counts.saveAsTextFile("s3://my-bucket/output/")

Stage 1.5 — Practical Component

What you should actually be able to do, not just know. Each item below now has the actual command/step, not just the checkbox.

  • [ ] Navigate a cloud console — log into the AWS Console → use the top search bar → type "EC2", "S3", "RDS" to jump straight to each service's dashboard.
  • [ ] Launch a basic VM (EC2)

    • ``bash # Via AWS CLI (after aws configure with your credentials): aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t2.micro \ --key-name my-key-pair \ --security-groups default ` Console alternative: EC2 → Launch Instance → pick Free Tier eligible AMI (e.g. Amazon Linux) → t2.micro → Launch → connect via "Connect" button (browser SSH) or your terminal: `bash ssh -i my-key-pair.pem ec2-user@<public-ip> ``

  • [ ] Create a storage bucket/container (S3)

    • ``bash aws s3 mb s3://my-analytics-bucket-2026 aws s3 cp local_file.csv s3://my-analytics-bucket-2026/ aws s3 ls s3://my-analytics-bucket-2026/ ` Same thing with Python's boto3 (useful since Glue/SageMaker/Lambda all use it too): ``python import boto3

s3 = boto3.client("s3") s3.create_bucket(Bucket="my-analytics-bucket-2026") s3.upload_file("local_file.csv", "my-analytics-bucket-2026", "local_file.csv")

for obj in s3.list_objects_v2(Bucket="my-analytics-bucket-2026")["Contents"]: print(obj["Key"]) ```

  • [ ] Explore basic database service setup (RDS) — Console: RDS → Create database → choose engine (e.g. PostgreSQL/MySQL) → Free tier template → note down the endpoint (hostname), port, username, and make sure the security group allows inbound traffic from your IP. Test connection:

    • ``bash psql -h <rds-endpoint> -U <username> -d postgres -p 5432 ``

  • [ ] MapReduce demonstration — trace the Word Count example above by hand on paper with a 3–4 word sentence of your own; then, if you have Spark set up locally or via a free Databricks community account, run the PySpark snippet above on a small .txt file to see it execute for real.

Module 1 — Self-Test (with Answer Key)

Try answering first, then check.

1. What are the 4 defining properties of cloud computing? > On-demand, Pay-as-you-go, Elasticity/Scalability, Managed infrastructure.

2. Name the AWS equivalents of Compute, Object Storage, and Managed SQL. > EC2, S3, RDS.

3. Why can't you just query SQL-style data sitting in S3 directly? > S3 only stores files — it has no query engine that understands rows/columns/relationships. You'd have to download and parse the whole file manually. (Note: this is also exactly what serverless querying tools like Athena solve in Module 3 — they let you run SQL directly on S3 without needing an RDS/warehouse.)

4. What's the difference between a data warehouse and a data lake (schema-on-write vs schema-on-read)? > A warehouse enforces structure before data is loaded (schema-on-write) — data must already be clean/structured. A lake stores raw data as-is and structure is applied only when you read/query it later (schema-on-read).

5. What's the difference between ETL and ELT? > ETL transforms data before loading it into the destination (needed for warehouses). ELT loads raw data first and transforms it later, inside the destination itself (common with modern lakes/warehouses that have their own compute).

6. Name the 3 Vs of big data. > Volume, Velocity, Variety. (Extended: + Veracity, Value.)

7. Why is Spark faster than Hadoop's MapReduce? > Spark keeps data in memory (RAM) across processing steps instead of writing intermediate results to disk after every step like Hadoop does — this avoids repeated slow disk I/O, giving roughly 10–100x speedup.

If you can answer all 7 without scrolling up, Module 1 is done — tick off Stage 1.1–1.5 in your tracker.
